## 0. 세션 시작 절차 (모든 워커 공통)

1. `git fetch && git checkout -B main origin/main` (pull --rebase 금지, 로컬 잔재 위에서 작업 금지)
2. SID 발급: `sess-HHMM-$RANDOM` (예: sess-0512-23481)
3. `PLAN.md` → `docs/ROUTINE.md` → `docs/PROGRESS.md` → `docs/claims/` 순서로 읽는다.
4. 아래 [2. 작업 목록]에서 **선점 가능한 가장 앞 작업**을 lock 으로 선점한다 (규약: `docs/claims/README.md`).
5. 선점할 작업이 없으면(전부 lock 또는 전부 완료): 마지막 완료 작업의 게이트를 재실행해 검증만 하고, 이상 없으면 **커밋 없이 조용히 종료**한다. 이상이 있으면 PROGRESS 에 등재하고 종료.

## 1. 절대 규칙

- **새 콘텐츠(특전/시스템/수치 체계) 임의 추가 금지.** 추가하고 싶으면 PROGRESS 에 «주인 승인 대기» 로 등재만 하고 넘어간다. (위임 규약: 밸런스 *숫자* 조정은 PLAN §7 범위 내에서 즉시 채택·진행하되 되돌림 가능하게 기록)
- 승인 프롬프트가 뜨는 명령을 피하고, 대화형 편집기(`git rebase -i` 등) 금지.
- 캡처 PNG·대용량 바이너리 커밋 금지. 증거는 md 의 수치로.
- 작업이 끝나면 lock 삭제 → PROGRESS 갱신 → 커밋 → push. **push 실패 시 `git pull --rebase=false` 말고 `git fetch && git rebase origin/main`** 후 재push (자기 lock 이 사라졌으면 진 것 — 작업 버리고 종료).
- 아티팩트 republish 는 **루틴 금지** (대화형 세션 전용 — PLAN §9-3). GitHub Pages 활성화도 주인 몫(PLAN §9-2). 루틴은 PROGRESS 에 «준비 완료» 표시까지만.
