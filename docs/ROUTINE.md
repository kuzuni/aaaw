> 이 문서와 `PLAN.md` 만 보고 작업한다. **PLAN.md 는 확정 스펙이라 임의 변경 금지** (밸런스 숫자 조정만 PLAN §7 범위 내 자율).
> 워커: **A :05 · B :20 · C :35 · D :50** (매시, 분 단위 슬롯 — 4개가 15분 간격으로 돈다. 전부 claude-opus-5).
> 보고·기록은 전부 **한국어**.

## ⚑ 신규 주인 지시 (위 항목이 최신)

- **(2026-09-02 06:2X KST) 특전 선택지 등급 통일** — 특전 선택지가 뜰 때 등급을 1번만 굴리고 3개(전지의 눈 4개) 전부 같은 등급으로. 섞어서 금지. 상세는 PLAN.md §3.0 에 반영해 둠. **T1 진행 세션은 다음 회차 전에 sim.js 에 즉시 반영할 것** (선택지 분포가 바뀌므로 반영 전 회차의 점수는 무효 — PROGRESS 회차 로그에 «등급통일 반영» 표시). T2 이식 시 index.html 도 동일 로직.

## 0. 세션 시작 절차 (모든 워커 공통)

1. `git fetch && git checkout -B main origin/main` (pull --rebase 금지, 로컬 잔재 위에서 작업 금지)
2. SID 발급: `sess-HHMM-$RANDOM` (예: sess-0512-23481)
3. `PLAN.md` → `docs/ROUTINE.md` → `docs/PROGRESS.md` → `docs/claims/` 순서로 읽는다.
4. 아래 [2. 작업 목록]에서 **선점 가능한 가장 앞 작업**을 lock 으로 선점한다 (규약: `docs/claims/README.md`).
5. 선점할 작업이 없으면(전부 lock 또는 전부 완료): 마지막 완료 작업의 게이트를 재실행해 검증만 하고, 이상 없으면 **커밋 없이 조용히 종료**한다. 이상이 있으면 PROGRESS 에 등재하고 종료.

## 1. 절대 규칙

- **새 콘텐츠(특전/시스템/수치 체계) 임의 추가 금지.** 추가하고 싶으면 PROGRESS 에 «주인 승인 대기» 로 등재만 하고 넘어간다. (위임 규약: 밸런스 *숫자* 조정은 PLAN §7 범위 내에서 즉시 채택·진행하되 되돌림 가능하게 기록)
- 승인 프롬프트가 뜨는 명령을 피하고, 대화형 편집기(`git rebase -i` 등) 금지.
- 캡처 PNG·대용량 바이너리 커밋 금지. 증거는 md 의 수치로.
- 작업이 끝나면 lock 삭제 → PROGRESS 갱신 → 커밋 → push. **push 실패 시 `git pull --rebase=false` 말고 `git fetch && git rebase origin/main`** 후 재push (자기 lock 이 사라졌으면 진 것 — 작업 버리고 종료).
- 아티팩트 republish 는 **루틴 금지** (대화형 세션 전용 — PLAN §9-3). GitHub Pages 활성화도 주인 몫(PLAN §9-2). 루틴은 PROGRESS 에 «준비 완료» 표시까지만.

## 2. 작업 목록 (순서 고정 — lock ID = 아래 번호)

### T1 — 밸런스 튜닝 루프 (비평가 2인 · 8점 게이트) ← 최우선
목표: `sim.js` 밸런스를 **비평가 2명이 각각 10점 만점에 8점 이상** 줄 때까지 조정.

한 회차(라운드) 절차:
1. `node sim.js 1` / `node sim.js 2` / `node sim.js 3` 실행, 원시 출력 저장 (`docs/balance/round-NN/` 에 md 로. NN = 회차 번호).
2. **비평가 2명을 Task(Agent) 도구로 각각 독립 실행** (서로의 결과를 보여주지 말 것). 각 비평가에게 주는 것: ①아래 채점표 ②이번 회차 시뮬 원시 출력 전문. 받는 것: 항목별 점수 + 총점(10점 만점) + 감점 사유 + 구체적 조정 제안.
3. 두 비평가 모두 **총점 ≥ 8** 이면 합격 → T1 완료 처리. 아니면:
4. 감점 사유를 근거로 `sim.js` 의 `TUNE` / 특전 수치 / 강화 비용 성장률 / 골드 드랍을 조정 (PLAN §7 의 노브만. 특전 개별 수치는 실험1·2 근거로만).
5. **조정한 수치를 PLAN.md §6·§3 에도 갱신 기록** (PLAN 의 요구사항).
6. 회차 결과를 PROGRESS 의 T1 행에 기록 (회차 번호 · 두 점수 · 무엇을 얼마로 바꿨는지 1줄씩) 하고 커밋·push. 다음 회차로.
- 세션 시간이 다 되어가면: 현재 회차까지 커밋·push, lock 삭제 후 종료 (다음 워커가 이어받는다).
- 세션이 90분을 넘기게 되면 lock 내용의 타임스탬프를 갱신해 push (탈취 방지).

**채점표 (비평가용, 총 10점):**
- 실험1 등급 사다리 (3점): 클리어율이 일반<희귀<전설<신화 로 단조증가하면 3점. 인접 역전 1쌍당 −1.5점.
- 실험2 등급 내 균형 (2점): 각 등급 내 (표본 ≥25판 특전 중) 승률 최상−최하 차가 전 등급 25%p 미만이면 2점. 25%p 이상인 등급 1개당 −1점.
- 실험3 진행 곡선 (5점): 챕터1~5 각 1~2회(1점) · 6~9 각 2~5회(1점) · **10이 10회 이상 & 400회 이내(2점 — 벽의 핵심)** · 11~19 각 3~10회 & 20이 10~30회(1점). 구간별로 어긋난 챕터가 있으면 해당 점수를 비례 감점.
- 비평가는 점수 외에 «가장 효과 클 조정 노브 1~2개» 를 반드시 제안할 것.

### T2 — index.html 이식 (T1 완료 후에만 선점 가능)
- T1 이 확정한 최종 수치·특전 102종·챕터 20개 구조를 PLAN §2~§6·§8 스펙대로 `index.html` 에 전면 이식. 메테오 등 구버전 잔재 완전 제거.
- `sim.js` 와 수식이 1:1 일치해야 함 (검증: 대표 수식 5개 이상을 grep 으로 대조해 PROGRESS 에 기록).
- 완료 게이트: `node --check` 급 문법 검사 + 특전 102종 전수 존재 확인 스크립트(`tools/verifyT2.js` 신설, 통과 수 기록).

### T3 — 동작 검증 (T2 완료 후)
- 가능하면 Playwright(`npx playwright install chromium` 후)로 헤드리스 부팅 → 콘솔 에러 0 · 로비 렌더 · 전투 진입 · 레벨업 특전 3택 노출까지 확인. Playwright 불가 환경이면 jsdom/정적 검사로 대체하고 그 사실을 기록.
- 발견 버그는 PROGRESS 에 번호 등재(T3-1, T3-2 …) 후 이 세션 또는 다음 워커가 수리.

### T4 — 배포 준비 (T3 완료 후)
- 최종 커밋·push 확인, PROGRESS 에 «주인 할 일» 정리: ① GitHub Pages 설정(https://github.com/kuzuni/aaaw/settings/pages, Branch=main, /(root)) ② 아티팩트 republish 는 대화형 세션에 요청.

### 신규 작업 등재
- 버그·후속 작업 발견 시 PROGRESS 표에 **이미 쓰인 번호 중 가장 큰 것 +1** 로 등재 (번호 재사용 금지, 한 번호 = 한 작업).
