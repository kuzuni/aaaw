> 이 표의 % 와 `tools/t3/shots.js` 가 낸 `layout.json` 의 % 를 나란히 놓고 **±3%p(프레임 기준)** 로 판정한다.

## ⚑ U01 회차 정정 (표를 쓰다 드러난 것 — ROUTINE ⑥ «표가 틀렸다고 보이면 고치되 회차 로그에 적는다»)

레퍼런스 쪽 % 는 그대로 유효하고, **게임 쪽을 «무엇으로 재는가» 에 함정이 하나 있다**:
`getBoundingClientRect` 는 **패딩까지 포함한 컨테이너**를 잰다. 그래서 다음 행들은 컨테이너를 재면
레퍼런스와 영영 안 맞는다 — 안쪽 요소로 판정할 것(하니스가 이미 둘 다 낸다).

| 행 | 컨테이너를 재면 | 판정에 쓸 것 |
|---|---|---|
| 로비 «상단 바» | `.lobby-top` = x0 y0 w100 **h8.2**(위 3.7% 여백을 품는다) | **아바타**(x2.5 y3.7 w9.7 h4.5) |
| 장비 «상단 바» | `.top-bar` = x0 y0 w100 h7.0 | 같은 방식 — 안쪽 pill 줄 |
| 장비·대장간 «인벤 그리드» | x0 w100 (안쪽 여백 3%) | **인벤칸 1·2·5·6** 의 x·w·h |
| 장비 «스탯 요약줄» | x0 w100 (안쪽 여백 10.5%) | 안쪽 칸 3개 |
| 대장간 «뒤로 줄» | x0 w100 | **`#fgBack` 버튼**(폭 17%) |
| 인게임 «상단 HUD 줄» | `#topbar` = 좌우 12px 여백 포함 | **킬 pill** |

또 한 가지 — **레퍼런스의 특전 «선택창»(perks.jpg) 에는 팝업 상자가 없다**(카드가 화면에 바로 놓인다).
상자가 있는 것은 **인포 팝업**(perks 뭐뭐 있는지.jpg)과 **장비 세부팝업**뿐이다. ⑦ 표의 «(인포 팝업) 박스» 행은

## ⚑ U02 회차 정정 (레퍼런스 % 는 그대로 · «게임 쪽을 어떻게 적는가» 의 정정 2건)

### ⓐ CSS 에 «프레임 %» 를 적을 때는 0.9755 로 나눈다 — `--fh` 는 프레임 높이가 **아니다**

U01 이 신설한 `--fh` 는 `min(100dvh, 100vw*19/9)` 인데, `#frame` 은 `height:100dvh` · `width:min(100vw, 100dvh*9/19)` 라
**잘리는 쪽은 높이가 아니라 폭**이다. 그래서 9:19.5 인 390×844 에서 `--fh = 823.3px` 이고 프레임 높이 844px 보다
**2.45% 작다**(360×800 이면 5%). 즉 `calc(var(--fh)*.28)` 은 프레임의 28% 가 아니라 **27.3%** 다.

- 지금 이 레포의 세로 값들은 **390×844 에서 실측으로 맞춘 것**이라 그 폭에서는 표와 맞는다.
- 새 값을 적을 때 규칙: **`calc(var(--fh) * (목표% ÷ 100 ÷ 0.9755))`** (예: 프레임 28% → `.287`).
- **U03 후보 과제**: `--fh:100dvh` 로 바로잡고 세로 값 전부를 ÷1.0251 로 되돌리면 어떤 기기에서도 표대로 선다.
  전 화면이 한꺼번에 움직이므로 **다른 수정과 섞지 말고 한 회차를 통째로 쓰는 편이 안전하다.**

### ⓑ 하니스가 못 재던 행 — 이제 표와 1:1 이다

U01 이 `tools/t3/shots.js` 에 적어 둔 gearpop 선택자 4개(`.gd-ic`·`.gd-contrib`·`.gd-opts`·`.gd-cost`)는

### ⓑ 늘 «없음» 이던 행 2개를 정리했다

- **대장간 «상단 바»** — ⑥ 표에 **그 행이 없다**(무대가 y0 부터 화면을 채운다). 게임에도 없으므로 지웠다.
- **인포 팝업 «닫기 안내»(`.tap-close`)** — 하니스가 찍는 상태(«선택창에서 연 책»)에는 그 요소가 존재하지 않는다.
  ⑦ 표의 «닫기 안내 y91.5» 자리를 게임에서 맡는 것은 `#pbBack` 이므로 **한 행으로 합쳤다**.
- **특전 획득창 «팝업 박스»** — ⑦ 선택창에는 상자가 없다(⚑U01 정정). 대응하는 ref 행이 없으므로 «(참고)» 로만 남긴다.

### ⓒ 선택자 앞의 `⊕` = «맞는 요소 전부의 합집합 상자»

ref 표의 «…줄(N칸)» 행은 컨테이너(좌우 여백 포함)가 아니라 **칸들이 실제로 차지한 폭**이다.
그것을 한 행으로 재려면 합집합이 필요하므로 하니스에 규칙을 넣었다(`'⊕#gearStats .gs'` 처럼 쓴다).

### ⓓ `#chapHud .nm` 은 `inline-block` 이어야 잰다

블록이면 상자가 늘 부모 폭(x0 w100)이라 ② 표의 «x36 w28» 과 영영 안 맞는다.
`inline-block` + 부모의 `text-align:center` 로 글자를 감싸야 자와 상자가 같은 것을 가리킨다(U03 이 고쳤다).

### ⓔ ⚠ `overflow:auto` 상자 안의 «위로 삐져나오는 라벨» 은 소리 없이 잘린다

인벤 부위 태그(`top:-6px`)·특전 카드 배지(`top:-11px`)가 스크롤 상자에 잘려 있었고,
**칸의 x/y/w/h 는 맞으니 레이아웃 표에는 안 잡힌다**(비평가가 스크린샷을 봐야 잡힌다).
고칠 때는 **위 여백을 주고 같은 값의 음수 `margin-top` 으로 상자를 끌어올린다** — 칸의 % 가 안 움직여야
이미 맞춰 둔 행들이 도미노로 어긋나지 않는다.
