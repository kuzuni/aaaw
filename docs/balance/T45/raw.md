# T45 — 소환 적중도 «공격» 이다 (주인 확정 15:3X) · 2026-09-02, sess-0807-26153 / 워커 A

주인 원문: «공격 시 50% 창이면, 창이 적 때렸을 때도 그 50% 적용. 치명타 시 창이면 창이 치명 뜨면 창 또 나가야 함.»

## 1. 무엇이 실제로 빠져 있었나

| 트리거 | 종전 동작 | 필요한 동작 |
|---|---|---|
| «치명타 시» | `dealDmg`/`dealPlayerDamage` **안**에 있어 기본공격 전용이 아니었다 → **소환 적중에도 이미 걸렸다** | 그대로 |
| «공격 시» | `procOnAttack()` 이 `playerStrike`(기본공격)에서만 불렸다 → **소환 적중은 아무 트리거도 안 굴렸다** | 소환 적중에도 굴린다 |

즉 이번 개정으로 새로 붙는 것은 **«공격 시» 쪽 하나**다. 종전 «기본공격에서만» 규칙에서 남는 것은 주인 위임대로
**`nextCrit`/`nextAtk` 소모 · 분신(`clone`) · 추가타(`extraHit`) 셋뿐**이다.

## 2. 구현 (sim.js ↔ index.html 같은 동사)

- `summonHit(e,ratio)` 신설 — 데미지 함수 호출 직후 `procOnAttack()`. **소환 적중 5경로 전부**가 이걸 거친다:
  번개(즉발 `fireBolts`) · 자동번개(`autoBolt`/`castBolt`) · 관통 투사체 적중(창·검기) · 단일 투사체 적중(도끼·화살).
- `pushProj(pr)` 신설 — 소환 투사체 생성을 한 곳으로 모았다(성능 가드가 걸리는 지점).
- 소환 적중은 데미지 함수에 «기본공격» 표시를 넘기지 않는다(sim 은 `fromBasic` 미전달, 게임은 아이콘 인자 필수)
  → **소환은 `nextCrit`/`nextAtk` 를 소모하지 않는다.**

### 성능 가드 2종 (주인이 명시 허용 — 확률·연쇄 자체는 제한하지 않는다)

| 상수 | 값 | 동작 |
|---|---|---|
| `PROJ_CAP` | 200 | 동시 활성 투사체 상한. **초과분은 «즉발 판정» 으로 대체** — 데미지가 사라지지 않는다. |
| `PROC_TICK_CAP` | 200 | 한 틱(프레임)에 굴리는 소환 적중 트리거 수 상한. 초과해도 **데미지는 그대로**, 트리거만 멈춘다. |

`PROC_TICK_CAP` 이 필요한 이유: 번개는 **즉발**이라 «번개 적중 → 공격 시 번개(10%) → 20발» 이 같은 틱 안에서 꼬리를 문다.
기대 분기수가 `0.10 × 20 = 2.0` 으로 1을 넘어 이론상 발산한다 — 밸런스 제한이 아니라 한 틱의 작업량을 유한하게 묶는 장치다.

등급이 높을수록 옵션 수가 많아 상승폭이 크다(전설 +28.5%p). **T1 은 이 상태에서 성장률·벽 배수를 다시 맞춰야 한다.**

## 4. 하니스 재보정 (정본 규칙 ④ — 노브를 바꾼 회차마다)

이 변경으로 하니스 클리어율이 밀려 `verifyHarness` 가 즉시 신호를 냈다(T31 이 정본화한 규칙이 처음으로 일한 사례).

같은 날 주인 지시 두 건이 **반대 방향으로** 하니스를 밀었다 — T43(적 회피 10%)은 내리고, T45(소환 트리거)는 올린다.

| 실험2 하니스 «일반+7·슬롯0» | 클리어율 |
|---|---|
| T31 재보정 시점 | 66.3% |
| T43(회피 10%)만 반영 | 55.0% — 밴드 하단 경계 |
| T45(소환 트리거)만 반영 | 77.7% — 밴드 이탈 |
| **둘 다 반영 (현재)** | **62.3% — 목표 밴드 정중앙** |

작업 중간 커밋에서 T45 단독 기준으로 «일반+6» 까지 내렸다가, 리베이스로 T43 이 들어온 뒤 재측정해 **일반+7 로 되돌렸다.**
둘 다 반영한 엔진에서 300판: 일반+6 44.3% · **일반+7 62.3%** · 일반+8 67.7% · 일반+9 75.7%.
실험1 은 일반+2·슬롯0 그대로 39.7%(사다리 4.0/33.7/62.0/76.0 — 비포화·인접 ≥2%p 만족).
새 기준선: 챕터6 `{일반+2·슬롯0, rate 39.7, gap −19.5}` · 챕터8 `{일반+7·슬롯0, rate 62.3, gap +32.3}`.

**실험1 재측정** (`SEED=1 node sim.js 1`, 현재 상태): 혼합 41.7% · 일반 6.7 < 희귀 35.3 < 전설 60.0 < 신화 73.7% — **단조증가 유지**.
⚑ T45 단독 시점에는 전설→신화 간격이 12.3 → 5.3%p 로 좁아졌었는데, T43 회피가 상단을 눌러 **13.7%p 로 회복**됐다.
⚑ 반대로 «일반» 칸이 6.7% 까지 내려왔다 — 여기서 더 내려가면 바닥 포화(1% 미만)라 하니스를 한 칸 올려야 한다(T1 감시 항목).

## 6. 게이트 (신설 2곳)

- `verifyCombatConst` **③** — vm 으로 엔진을 **실제로 굴려** 단언한다: 소환 적중 1회가 «공격 시» 트리거를 굴리는가 ·
  기본공격 전용 자원(`nextCrit`/`nextAtk`)을 안 먹는가 · 틱 예산 초과 시 «데미지는 그대로, 트리거만 정지» 인가 ·
  투사체 상한 초과분이 즉발 판정으로 대체되는가 · PLAN §4 주인 확정 문구가 살아 있는가. **①에 가드 2종의 PLAN↔엔진 대조도 추가**(25항목).
- `verifyT2` **⑳** — 두 파일 대조: 가드 상수 일치 · 소환 적중 7경로가 전부 `summonHit` · 투사체 생성이 전부 `pushProj`
  (직접 `G.pprojs.push` 0건) · 기본공격 전용 3종 잔존.

## 7. 다른 워커 변경과의 병합 메모

- **T44(관통형은 스폰된 적만)**: 관통 투사체가 `node`(발사 시점 최전방 적의 웨이브)를 들고 다니며 그 웨이브만 때린다. `pushProj` 의 «즉발 판정» 경로에도 같은 필터(`!pr.node||e.wave===pr.node`)를 걸었다 — 상한을 넘겼다고 미스폰 적을 때리면 T44 가 깨진다.
- **T43(적 회피 10%)**: 소환 적중도 회피 판정을 거치므로(데미지 함수 안), 빗맞은 소환은 데미지도 트리거도 없다. 별도 처리 불필요.
- `verifyT2` 항목 번호는 T43 이 ⑳ 을 먼저 쓰고 있어 이 작업분은 **㉑** 로 등재했다.
