   신화 풀셋 +9강 · 슬롯 150 세이브로 챕터 1·50·150·250·300 을 실부팅해 자동 전투.

   **그런데 챕터 150 이 «💀 처치: 0» 으로 클리어됐다** — 챕터 1 은 41 처치였다. 여기서 시작했다.

## 1. 원인

`index.html` 보스 `onKill`:

```js
if(e.isBoss){
  G.cleared=true; shake(10);
  gainExp(...);
  setTimeout(()=>{ if(G) openClear(); },700);   // ← 클리어 화면만 700ms 미룬다
}
```

`G.over` 는 `openClear`/`openDead` 안에서만 켜지므로 **그 0.7초 동안 `G.over` 는 false**,
`update()`(`if(!G.paused&&!G.over)`)가 계속 돈다. 즉 «보스는 죽었는데 챕터는 안 끝난» 창이 있다.

`sim.js` 는 이 창이 **없다** — 전투 루프가

```js
while(!G.dead && !G.cleared && G.t<maxT){ ... }      // sim.js:1003
```

라서 보스가 죽는 순간(`if(e.isBoss)G.cleared=true;` sim.js:705) 챕터가 끝난다.
**즉 sim↔게임 괴리이고, 옳은 쪽은 sim 이다.**

## 2. 실측 재현 (헤드리스 · 전부 정상 엔진 경로)

### ① 창 안에서 죽으면 «💀 사망» 이 «🏆 클리어» 로 덮인다 — 죽었는데 클리어

보스가 잡몹보다 먼저 죽는 상태를 만든다(관통 창·번개·도끼 등 원거리 소환이면 정상 상황이다.
`aliveEnemies()` 는 전 노드를 훑으므로 잡몹이 남은 채로 보스가 죽을 수 있다). 잡몹 1마리만 남기고
플레이어 hp 1 로 두고 보스를 `onKill` 한 뒤, **손대지 않고 update() 만 굴렸다**:

```
t0     cleared=true over=false 생존적=1 hp=1
+100ms hp=0 over=true  화면=💀/쓰러졌다...
+200ms hp=0 over=true  화면=💀/쓰러졌다...
...
+600ms hp=0 over=true  화면=💀/쓰러졌다...
+700ms hp=0 over=true  화면=🏆/챕터 1 클리어!      ← 사망 화면을 덮는다
최종   화면=🏆 챕터 1 클리어!  maxChapter=2        ← 해금·클리어 보너스까지 지급
```

플레이어 눈에는 **«쓰러졌다» 가 0.6초 떠 있다가 «클리어» 로 바뀐다.**

### ② 전투가 실제로 0.7초 더 돈다 (창의 존재 증명)

보스 사망 뒤 `G.t` 를 100ms 마다 읽었다 — `0.10 → 0.70s` 로 **정확히 700ms 만큼 전투 시간이 흐른다.**
(보스가 마지막 1마리인 흔한 경우는 `if(!alive.length) return;` 에 걸려 이미 멈춰 있었다.
그래서 이 결함은 «잡몹이 남은 채 보스가 먼저 죽는» 경우에만 드러난다.)

### ③ 창 안에 다른 챕터를 시작하면 그 챕터가 공짜로 클리어된다

`setTimeout` 안의 가드가 `if(G)` 였다 — «그 전투» 가 아니라 «그때의 전역 G» 를 본다.
챕터 1 보스 처치 → 포기하고 로비로 → 챕터 40 START (전부 실제 유저 경로) 를 창 안에서 하면:

```
t0     챕터1 보스사망 (openClear 700ms 예약)
t+0    챕터40 시작: G.chapter=40 kills=0
t+900ms 화면="🏆 / 챕터 40 클리어! / 💀 처치: 0 / 🪙 획득 골드: 280.04K (보너스 +280.04K)"
```

**한 대도 안 때린 챕터 40 이 클리어 처리되고 클리어 보너스 280.04K 가 지급된다.**
(§0 에서 본 «챕터 150 처치 0 클리어» 가 바로 이것이었다 — 프로브가 챕터 50 을 창 안에서 갈아탔다.)

### ④ 반대 방향 — 창 안에 나가면 정당한 클리어가 증발한다

같은 자리의 대칭 증상. 보스를 죽이고 0.7초 안에 «포기하고 로비로» 를 누르면 `G=null` 이라
`if(G)` 가 막아 `openClear` 가 아예 안 열린다 → 해금도 클리어 보너스도 없다.

## 3. 수정 (index.html 4곳 · sim.js 무수정)

| 자리 | 종전 | 수정 |
|---|---|---|
| `update()` 조기 반환 | `if(!alive.length) return;` | `if(!alive.length \|\| G.cleared) return;` |
| 보스 `onKill` 예약 | `setTimeout(()=>{ if(G) openClear(); },700)` | `const g=G; setTimeout(()=>{ if(G===g) openClear(); },700)` |
| `menuBtn` 가드 | `if(!G\|\|G.over\|\|G.paused) return;` | `… \|\|G.cleared) return;` |
| `openDead()` | (가드 없음) | 맨 앞에 `if(G.cleared) return;` |

- 첫 줄이 본체다 — **보스가 죽으면 그 틱부터 전투가 멈춘다(sim 과 동일).** 보스가 마지막 1마리인
  경우는 원래 `!alive.length` 로 같은 자리에서 멈추고 있었으므로 **두 경우를 같게 만드는 것**이지
  새 동작을 넣는 게 아니다. 연출(파티클·플로팅 텍스트·번개·낫)은 이 반환 «위» 에서 갱신되므로 그대로 흐른다.
- 나머지 셋은 같은 창의 다른 입구를 막는 방어선이다. `menuBtn` 가드가 ③·④ 의 유일한 유저 입구를 닫는다.
- **`sim.js` 는 한 줄도 안 건드렸다 — 밸런스 영향 0, T1 회차 무효 아님.**

### 수정 후 재측정

```
① t0 cleared=true → +100~600ms hp=1 over=false 화면 없음 → +700ms 🏆 클리어  (사망 화면 소멸)
③ t+900ms 화면="(없음)"  maxChapter 불변                                  (공짜 클리어 차단)
```
