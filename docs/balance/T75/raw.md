# T75 — 실험3 «재시도 상한» ↔ «채점 목표 상한» 분리 (근거)

세션 `sess-2021-5216` / 워커 B · 2026-09-02T20:2X~20:5XZ · 엔진 밸런스 **무수정**(하니스 상한 1개만 변경).

## 1. 무엇이 문제였나

`sim.js` 의 실험3 하니스는 한 챕터를 `EXP3_LIMIT`(기본 **400**)회까지 재도전하고 실패하면 런을 끊었다.
그런데 `tools/scoreExp3.js` 의 벽 구간 목표 상한도 **400** 이었다. 같은 숫자라서:

1. **목표 «30~400회» 가 사실은 «30~399회»** — 400 에 닿은 셀은 언제나 «400회 실패» 로 적히고
   채점기는 `r.failed` 셀을 무조건 부적합으로 센다. 즉 문서에 적힌 상한이 원리적으로 도달 불가능했다.
2. **«401회면 뚫었을 계정» 과 «4,000회여도 못 뚫을 계정» 이 한 칸에 뭉개졌다.**

## 2. 무엇을 고쳤나

- `sim.js` — `const EXP3_TRY_LIMIT=1000` 신설(환경변수 `EXP3_LIMIT` 로 덮어쓰기 유지).
  원시 출력 헤더에 «재시도 상한 N회» 를 찍어 **출력만 봐도 어떤 자로 쟀는지** 알 수 있게 했다.
- `tools/scoreExp3.js` — 채점 목표 400 은 **그대로**. 헤더(없으면 실패 셀의 시도 수)에서 상한을 읽어,
  상한이 목표 상한 이하인 원시 출력에는 ⚠ 경고를 찍는다(= T75 이전 자로 잰 자료 판별).
- `tools/verifyScoreCriteria.js` — 종전의 «EXP3_LIMIT == 400» 단언을 **«상한 > 목표 상한»** 으로 뒤집고,
  T80 선례대로 상수 선언·기본값 배선·헤더 표기 3자리를 같이 본다.
- `tools/verifyScoreExp3.js` — 행동 단언 ⑧~⑪ 추가(9 → **18항목**).
- `PLAN.md` §7 실험3 절에 두 상한의 구별과 «이전 회차 총점과 직접 비교 금지» 를 기재.
