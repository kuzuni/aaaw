## 1. T19 — «효과 포화» 축의 미등재 건 (계열 **간** 누적)

### 1-a. 왜 T14 가 이걸 못 봤나

T14(워커 D)는 «한 계열 안에서 두 옵션이 같은 `px` 키를 `++` 하는가» 를 검사해 `chain`(사슬갑옷) 1건을 잡았다.
그 검사는 구조적으로 **부위가 다른 두 계열이 같은 키를 올리는 경우**를 볼 수 없다.

`tools/verifySaturation.js` (이번에 신설) 로 두 축을 동시에 전수 검사한 결과:

```
=== 효과 포화 대조 (T19 게이트) ===
  대상: 18계열 126칸 · pkk 확률 키 34종

[① 계열 내부 누적 — 신화 +9강(옵1~7 전부) 기준]
  사슬갑옷(chain) px.thorns ×2 → 60.0% × 2 = 120.0%  [옵2(영웅) + 옵5(신화 +3강)]      ← T14 기등재
  (그 외 계열 내부 중복 3쌍 — 전투도끼 axe 30.0% · 장궁 arrow2 30.0% · 구슬 spear 15.0% — 전부 1.0 미만이라 정상)

[② 계열 간 동시 장착 누적 — 부위마다 1계열만 장착 가능]
  px.extraHit ×2 → 75.0% × 2 = 150.0%  [장궁(bow) 옵5(신화 +3강) + 건틀릿(gauntlet) 옵6(신화 +6강)]   ← 🔴 미등재
  px.killCritBuff ×2 → 30.0% × 2 = 60.0%  [왕관 + 부적]   ← 정상

[③ 상한 스탯 — 장비만으로 상한에 닿는가]
  def:   기본 5 + 장비 최대 26 = 31 / 상한 80 → 여유 49  [투구 +14 + 사슬갑옷 +12]
  evade: 기본 8 + 장비 최대 15 = 23 / 상한 90 → 여유 67  [샌들 +15]
```

### 1-b. 발견 — `extraHit` 계열 간 포화

| | 값 |
|---|---|
| 엔진 | `sim.js:695` `if(crit&&px.extraHit&&pkk(p,0.75*px.extraHit)&&e.hp>0)dealDmg(G,e,2.3);` |
| 출처 1 | `sim.js:255` 장궁 옵5 «치명타 시 75% 확률 추가타» (신화 +3강에 열림) |
| 출처 2 | `sim.js:322` 건틀릿 옵6 «치명타 시 75% 확률 추가타» (신화 +6강에 열림) |
| 두 부위 | 무기 · 장갑 — **동시 장착 가능** |
| 합산 확률 | `0.75 × 2 = 1.50` |
| 광고된 상승 | +75%p |
| 실효 상승 | **+25%p** (100% 에서 잘림) |
| 버려지는 분 | **50%p** — T14 의 사슬갑옷(20%p)보다 2.5배 크다 |
| 덤 | `m_procX2`(모든 발동 확률 ×1.22)가 이 조합에서 완전 무효 |

**두 설명문은 각각 엔진 상수(0.75)와 정확히 일치한다** — 그래서 T17 게이트(`verifyOptText.js`)는 통과한다.
포화는 «숫자가 틀린 것» 이 아니라 «맞는 숫자끼리 합쳐서 상한을 넘는 것» 이라 기존 두 게이트가 원리상 못 잡는다.

### 1-c. 발현 조건

- 장궁 신화 +3강 **그리고** 건틀릿 신화 +6강 이상 → 즉 §11.7 앵커 B(신화 풀셋 +9강) 등급대.
- 다만 **실험5 앵커 하니스는 이 조합을 절대 만들지 않는다**(아래 T20 — 무기는 항상 대검 고정). 실제로 이 포화를 맞는 것은 **뽑기로 굴러가는 실험4·실전 플레이어**뿐이다.
  - (T14 가 «영향 범위는 앵커 B 하나» 라고 적은 것도 같은 이유로 정정 대상이다 — 앵커 빌드의 갑옷은 항상 판금이라 사슬갑옷은 앵커 측정에 **한 번도 등장하지 않는다**.)

### 1-d. 신설 게이트

`tools/verifySaturation.js` — 3축(계열 내부 · 계열 간 · 상한 스탯) + `procX2` 경계 경고.
- 정상 통과 확인: exit 0, «신규 포화 0건 · 등재된 기존 포화 2건».
- 실패 경로 확인: `KNOWN` 에서 `cross|extraHit` 를 뺀 사본에서 exit 1 + 해당 줄 🔴 출력.
- 하드코딩 없음 — 계열·부위·이름표를 `GT` 에서, 기저 확률을 `pkk(...)` 호출부에서 뽑는다. 18계열 126칸이 아니면 즉시 실패한다.

## 2. T20 — 앵커 3점·실험1·2 가 18계열 중 **6계열만** 측정한다

### 2-a. 원인 (1줄)

`sim.js:464` `mkBuild(rar,plus,slotLv,typeIdx)` 가 `GT.types[pt][typeIdx||0]` 이고,
**호출자 전원이 `typeIdx` 를 넘기지 않는다**:

| 호출부 | 채점 배점 | 실제로 도는 계열 |
|---|---|---|
| `sim.js:901` `harness()` → 실험1 | 사다리 **3점** | typeIdx 0 |
| `sim.js:901` `harness()` → 실험2 | 등급 내 **2점** | typeIdx 0 |
| `sim.js:1014` `exp5_anchor()` | 앵커 **2점** | typeIdx 0 |

typeIdx 0 = **대검 · 투구 · 판금갑옷 · 건틀릿 · 샌들 · 펜던트** 6계열.
즉 **채점표 10점 중 7점이 18계열 중 6계열(3^6 = 729 조합 중 1조합)에서만 매겨진다.**
(실험3·4 는 뽑기로 계열이 섞이므로 이 문제에서 자유롭다.)

### 2-b. 실측 — 같은 등급·같은 강화·같은 슬롯인데 클리어율이 0.8% ~ 100%

균등 조합 3개(모든 부위를 같은 typeIdx 로)만 돌린 값이다. 앵커 스펙(등급·강화·슬롯)은 §11.7 그대로.

### 2-c. 무엇이 깨지는가

1. **«챕터 90 대형 벽»·«챕터 300 최종 벽» 이 주인 확정 스펙인데 계열 조합에 따라 통째로 사라진다.**
   idx2 조합은 앵커 A 스펙(신화 0강·슬롯 15)만으로 챕터 90·91·92 를 **전부 100%** 로 지나간다. 벽이 아니라 평지다.
   앵커 B 도 idx1·idx2 는 챕터 300·301 이 100% 다 — «301+ 가 사실상 벽» 이라는 §11.7 서술과 정면으로 어긋난다.
2. **승인 대기 14번(T18, «챕터 90 벽이 사라졌다»)의 원인 진단이 좁았다.**
   14번은 붕괴 원인을 `slotCostG` 3.5 로 인한 «도달 시점 슬롯 15→16렙 이탈» 하나로 잡았는데,
   **슬롯을 앵커 스펙 15렙에 고정한 채 계열 조합만 바꿔도 90 벽은 5.0% → 100.0% 로 무너진다.**
   즉 두 축이 독립으로 있고, 계열 축이 더 크다. (14번의 선택지는 여전히 유효하나, 그것만 골라도 90 벽은 idx2 플레이어에게 안 선다.)
3. **실험1 사다리 3점·실험2 등급 내 2점도 같은 6계열 위에서만 매겨졌다** — 여태 나온 사다리 수치(5.7/15.0/46.7/80.0% 등)는 «대검 계열 플레이어의 사다리» 다.

### 2-d. 근인 — «소환 발수 증폭» 옵션이 옵4 자리에서 계열마다 자릿수로 다르다

각 계열 옵4(= 신화 0강에 열리는 마지막 옵션, 앵커 A 의 마지막 옵션)를 나란히 놓으면 원인이 바로 보인다:

| 부위 | idx0 | idx1 | idx2 |
|---|---|---|---|
| 무기 | 대검 «검기 관통 20·사거리 1400» | 도끼 «**도끼 14개로 증가**» (1→14, ×14) | 장궁 «**화살 24발로 증가**» (2→24, ×12) |
| 투구 | 투구 «피격 시 30% 확률 방어 +14 4초» | 왕관 «처치 시 30% 확률 치명 +14 4초» | 두건 «**번개 20회로 증가**» (2→20, ×10) |
| 목걸이 | 펜던트 «회복 시 20% 확률 실드 3%» | 부적 «처치 시 30% 확률 치명 +14 4초» | 구슬 «**창 피해 13.5배·관통**» (×13.5) |

- **idx2 조합은 소환 3종(화살·번개·창)의 증폭을 한 빌드에 동시에 갖는다** — 그래서 100% 가 나온다.
- idx0 조합의 옵4 는 전부 «확률 발동 소폭 버프» 라 자릿수 기여가 없다.
- 이 배치는 T6 이 18계열 옵션표를 초안할 때 «계열 정체성» 기준으로 짠 결과이고, **계열 간 전투력 균형은 한 번도 측정된 적이 없다**(측정 도구가 typeIdx 0 고정이었으므로).

### 2-e. 워커가 자율로 못 고치는 이유

- 옵션 배치를 옮기는 것은 §7 위임 노브(경제 3개) 밖의 **수치 «체계» 변경**이고, §11.6 옵션표는 주인 검토를 거친 표다.
- 앵커 스펙(§11.7 등급·강화·슬롯)은 주인 확정 상수다. «앵커가 어느 계열 조합 기준인가» 는 스펙에 적혀 있지 않아 **해석이 아니라 결정**이 필요하다.
- → 승인 대기 16번에 선택지 3안으로 등재.
